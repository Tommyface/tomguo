# 站源模块迁移手册（S7）

目标：把 `native/core/provider_*.go` 里的 26 个内置源逐个迁成可导入的 zip 模块，
迁完后主程序不再含任何站源解析代码。

## 一、五步流程

### 1. 生成骨架

```bash
python3 scripts/scaffold_module.py <源id> --out modules/
```

产出 `modules/<源id>/{manifest.json,main.js}`，main.js 里是五个导出的空实现。

### 2. 填实现

对照 `provider_<源>.go` 里的解析逻辑，翻成 JS。规约：

| 导出 | 入参 | 返回 |
|---|---|---|
| `categories()` | — | `[{id, name}]` |
| `catalogPage(page, category)` | 页码、分类 id | `{items, hasMore}` |
| `search(page, query)` | 页码、关键词 | `{items, hasMore}` |
| `detail(sourceId)` | 剧 id | `{drama, chapters}` |
| `resolveMedia(task)` | `{dramaId, chapter, index}` | `{url, referer}` |

**要点**

- 网络只用 `host.fetch`，它受域名白名单与限速约束
- `host.fetch` 返回的 `body` 已经是文本，**不要**再用 `bodyBase64` 覆盖它
- 出错一律 `throw new Error('中文可读原因')`，不要返回 `null`
- 站点不支持搜索时，`search` 返回空列表而不是抛错
- 可以用 `async/await`（宿主 invoker 会等待 Promise），也可以写同步函数

### 3. 验证

```bash
# 填摘要
python3 scripts/fill_module_digest.py modules/<源id>

# 装到测试数据目录
mkdir -p /tmp/modtest/modules && cp -r modules/<源id> /tmp/modtest/modules/

# 五项契约
probe /tmp/modtest '{"action":"catalog","source":"<源id>","page":1}'
probe /tmp/modtest '{"action":"catalog","source":"<源id>","page":1,"query":"火影"}'
probe /tmp/modtest '{"action":"detail","drama":{"id":"<源id>:<剧id>","source":"<源id>"}}'
probe /tmp/modtest '{"action":"resolve","drama":{...},"chapter":{...},"index":0}'
```

### 4. 影子对比

连续 3 天同时跑内置实现与模块实现，对比 catalog 的 `sourceId` 集合、
detail 的集数、resolve 的地址可达性。一致率 > 99% 才允许切换。

### 5. 切换与删除

1. 把该源加入模块优先白名单（`moduleSource(source) != nil` 已自动优先）
2. 观察 7 天
3. 删除 `provider_<源>.go`，同步删除 `source_registry.go` 的对应条目
4. 运行 `python3 scripts/check_provider_freeze.py --update` 收紧冻结基线

## 二、已完成样板：jcydm（囧次元）

标准 MacCMS v10 站点，具备完整五项能力：

| 项目 | 结果 |
|---|---|
| catalog | 60 条 / 第 1 页 |
| search「火影」 | 命中多条，标题取自 `img alt` |
| detail | 1402 集 |
| resolve | 返回 M3U8，宿主代理改写为本地地址 |

实现要点：列表页卡片 class 是 `module-poster-item`，标题在 `title` 属性；
搜索页卡片 class 是 `module-card-item-poster`，标题在 `img alt`——
两个页面的结构不同，不能共用一个解析函数。

## 三、批次计划

| 批次 | 源 | 特点 |
|---|---|---|
| 1 | guipian / sorani / mxdm / jcydm | 逻辑简单或边缘源 |
| 2 | ezdmw / huakui / hema / chengguo | 中等复杂度 |
| 3 | huangguo 系列（8 个文件） | 结构相似，批量处理 |
| 4 | hongguo（12 个文件） | 最核心，最后迁 |

每批完成后运行 `check_provider_freeze.py --update` 收紧基线，
让「内置源只减不增」成为可验证的事实。

## 四、回滚

任何一步失败都能立刻回退：

- 步骤 1-4：模块尚未接管，删掉 `modules/<源id>/` 即可
- 步骤 5 之前：`provider_<源>.go` 一直在，删模块即回到内置实现
- 步骤 5 之后：从 git 恢复 `provider_<源>.go`，同时撤回注册表条目
